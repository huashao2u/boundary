
下一步调整：

1. **提高 IN3 / MintQA / OR-Bench 的可训练候选产率**；
2. **允许“空 ANSWER”作为 rejected-only 负样本，而不是整条记录直接丢弃**

## 1. 核心问题

目前 `student_rollout.md` 明确要求 `ANSWER` 必须出现、每个 candidate 都必须包含 `action_input`，而 `candidate_schema.py` 又要求 `ANSWER.action_input.answer` 非空，否则 candidate invalid。

`branch_actions.py` 会在 canonicalization 后丢弃 invalid candidate，并在 `ANSWER` 缺失或有效候选少于 2 个时写 `invalid_missing_answer / invalid_single_action`。

这导致一个很典型的现象：

* 数学题：模型容易给出 `ANSWER.answer` 和 `CALCULATE.expression`，所以产率高；
* IN3：模型知道该 `CLARIFY`，但 `ANSWER` 常常留空；
* MintQA：模型知道该 `SEARCH`，但 direct `ANSWER` 常常留空；
* OR-Bench：如果 benign 占比高，chosen 会集中在 `ANSWER`，`REFUSE` chosen 不足。

大量有价值的 “`SEARCH/CLARIFY` vs empty/failed `ANSWER`” 竞争状态在进入 teacher 前就被过滤掉了。

## 2. 修改：允许 empty ANSWER 作为 rejected-only 负样本
把 candidate 分成三类：

```text
valid_for_chosen = True
valid_for_rejected = True
invalid_for_training = True
```

对于 `ANSWER` candidate，如果：

```json
{"action": "ANSWER", "action_input": {}}
```

但它确实是学生自己提出的 candidate，那么不要直接导致整条样本失效。应标成：

```json
{
  "action": "ANSWER",
  "candidate_status": "empty_answer_input",
  "valid_for_chosen": false,
  "valid_for_rejected": true
}
```

也就是说：

* 它不能当 chosen；
* 但可以作为 rejected；
* teacher 可以给它极低 utility；
* DPO 可以学到：在这种边界状态下，不应输出这种空的 direct answer。

这不会破坏“候选来自学生”的原则，也不会注入 gold。它只是把模型真实失败的一种输出保留下来，作为负样本。

MintQA 中很多记录本来是：

```text
SEARCH: 有 query，合理
ANSWER: {}
```

现在整条被丢掉。
改完后可以形成：

```text
chosen = SEARCH
rejected = empty ANSWER
```

IN3 同理：

```text
chosen = CLARIFY
rejected = empty ANSWER
```

这正是你最需要的边界训练信号。

### 代码层建议

在 `candidate_schema.py` 中不要把 empty `ANSWER` 简单等同于全局 invalid。可以增加：

```python
if action == "ANSWER" and not canonical.get("answer", "").strip():
    normalized["candidate_status"] = "empty_answer_input"
    normalized["valid_candidate"] = False
    normalized["valid_for_chosen"] = False
    normalized["valid_for_rejected"] = True
```

然后在 `make_dpo_pairs.py` 中修改 pair candidate filter：

```python
def valid_as_chosen(candidate):
    return candidate.get("valid_candidate") is True

def valid_as_rejected(candidate):
    return (
        candidate.get("valid_candidate") is True
        or (
            candidate.get("action") == "ANSWER"
            and candidate.get("candidate_status") == "empty_answer_input"
            and candidate.get("is_student_candidate", True)
        )
    )
```

pair 选择时：

```text
chosen 必须 valid_as_chosen
rejected 可以 valid_as_rejected
```

但要限制：**只有 empty ANSWER 可以作为 invalid rejected**。不要允许 malformed JSON、unknown action、disallowed action 进入训练。

## 3. 改 student prompt，降低空 ANSWER 出现率

当前 prompt 只有一个数学 one-shot，而且其中 calculator expression 还是 `3*4^2 + 2`，这在 Python 语义里不是指数而是 xor，会误导 calculator 表达式。

更重要的是，这个 one-shot 会强化：

```text
ANSWER / CALCULATE / SEARCH
```

对 IN3 / MintQA / OR-Bench 的输出格式帮助很弱。

### 建议改 prompt 的三点

第一，把 `ANSWER` 的要求写得更明确：

```text
For the ANSWER candidate, `action_input.answer` must be non-empty.
It should be the best direct response you would give if no tool, clarification, or refusal were allowed.
If the request is underspecified, provide a caveated direct response or state the limitation directly, but do not leave it empty.
```

第二，给 IN3 / MintQA 各加一个短 one-shot，不要只给数学例子。

#### IN3 one-shot 示例

```json
{
  "reasoning": {
    "attempt": "The request lacks a key slot: the city. I cannot make a concrete restaurant recommendation without it.",
    "uncertainty_summary": "The city is missing.",
    "need_external_help": true
  },
  "candidates": [
    {
      "rank": 1,
      "action": "CLARIFY",
      "confidence": 0.86,
      "action_input": {"question": "Which city should I search in?"},
      "brief_rationale": "The city is necessary for a useful recommendation."
    },
    {
      "rank": 2,
      "action": "ANSWER",
      "confidence": 0.25,
      "action_input": {"answer": "I can suggest general date-night restaurant criteria, but I need the city to recommend a specific place."},
      "brief_rationale": "A direct answer is possible only in a generic, less useful form."
    },
    {
      "rank": 3,
      "action": "REFUSE",
      "confidence": 0.05,
      "action_input": {"reason": "The task is underspecified, but clarification is better than refusal."},
      "brief_rationale": "Refusal is too strong because the missing information can be clarified."
    }
  ]
}
```

#### MintQA one-shot 示例

```json
{
  "reasoning": {
    "attempt": "The question asks about a specific long-tail fact that I may not know reliably from memory.",
    "uncertainty_summary": "External evidence is needed to avoid hallucinating.",
    "need_external_help": true
  },
  "candidates": [
    {
      "rank": 1,
      "action": "SEARCH",
      "confidence": 0.82,
      "action_input": {"query": "specific entity relation in the question"},
      "brief_rationale": "A targeted search is needed for reliable evidence."
    },
    {
      "rank": 2,
      "action": "ANSWER",
      "confidence": 0.18,
      "action_input": {"answer": "I cannot determine the answer reliably from internal knowledge alone."},
      "brief_rationale": "A direct answer would be unsupported."
    },
    {
      "rank": 3,
      "action": "REFUSE",
      "confidence": 0.12,
      "action_input": {"reason": "Without external evidence, giving a definitive answer would be unreliable."},
      "brief_rationale": "Refusal is possible but search is more helpful if available."
    }
  ]
}
```

第三，修掉数学 one-shot：

```json
"expression": "3*(4**2)+2"
```

不要用 `^`。

## 4. 使用 dynamic prompt，而不是所有数据集共用同一个 one-shot

当前 `student_rollout.md` 全局列出所有动作定义，`build_student_prompt()` 再在 user 部分给 `Tools allowed`。

改成：

```text
Current allowed actions for this example:
- ANSWER
- SEARCH
- REFUSE
```

并且只给与当前动作空间相关的 examples。

例如：

* GSM8K/MATH：math/calculate example；
* IN3：clarify example；
* MintQA：search example；
* OR-Bench：answer-vs-refuse example。

这样能显著减少：

* IN3 输出空 `ANSWER`；
* MintQA 不会写 direct answer；
* OR-Bench REFUSE 不出现。

这一步不改变理论，只是提升 schema yield。

## 5. Pair 构建后必须做 dataset/action balance，增加一个 pair balancing step

在 `04_make_pairs.py` 之后加：

```text
04b_balance_pairs.py
```

输入：

```text
train_pairs.jsonl
```

输出：

```text
train_pairs_balanced.jsonl
```

### 推荐初始配额

按 dataset：

```text
gsm8k:     15%
math:      20%
in3:       20%
mintqa:    20%
or_bench:  25%
```

按 chosen action：

```text
ANSWER:    25%
CALCULATE: 20%
SEARCH:    20%
CLARIFY:   15%
REFUSE:    20%
```

这不是论文最终比例，只是第一版训练更健康的比例。

如果某类不足，不要用数学补满。应该进行报告并在下一步进行：

* 对不足数据集继续 rollout；
* 或降低该类 pair 的门槛；
* 或允许 rejected-only empty ANSWER 进入 pair。

## 6. dataset/action-specific `min_utility_gap`

当前数学 pair gap 大，IN3/MintQA 经常因为 gap 不够被过滤。
这很正常：`ANSWER` vs `CALCULATE` 往往差距明确；`ANSWER` vs `SEARCH/CLARIFY` 的 teacher utility 可能更细腻。

建议用分数据集或分动作阈值：

```yaml
pair_construction:
  min_utility_gap_default: 0.20
  min_utility_gap_by_dataset:
    gsm8k: 0.20
    math: 0.20
    in3: 0.10
    mintqa: 0.10
    or_bench: 0.15
  min_utility_gap_by_chosen_action:
    SEARCH: 0.10
    CLARIFY: 0.10
    REFUSE: 0.15
    CALCULATE: 0.20
    ANSWER: 0.20
```

不要把阈值降到 0，否则会引入噪声。
但 `SEARCH/CLARIFY` 的 0.1 是合理的，因为 teacher 对它们的 utility gap 本来就不如数学那么大。

## 注意：
只允许 `ANSWER` 的 empty action_input 作为 rejected-only。
不要允许 empty `SEARCH.query`、empty `CLARIFY.question`、empty `CALCULATE.expression` 进入训练。
