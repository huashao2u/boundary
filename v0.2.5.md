# v0.2.5 修改指导：Teacher Self-Evidence Relabel + Payload-First Utility

> 适用代码基线：`boundary` v0.2.4
> 目标：在**不重跑昂贵 student rollout** 的前提下，修复 teacher utility 对数学样本与 payload/rationale 冲突的误判，提升 pair 质量，然后再决定是否扩大 DPO 训练。

---

## 0. 当前问题总结

v0.2.4 的主链路已经基本干净：

- pair 来自真实 student candidates；
- teacher label 来源是 poe teacher；
- message DPO 已接入；
- empty ANSWER rejected-only 已实现；
- vLLM candidate action logprob scoring 已实现；
- OR-Bench 已接入；
- `U_rel` 默认使用 teacher utility。

但人工 review 暴露了新的核心问题：

1. `ANSWER.action_input.answer` 错，但 teacher 给高分；
2. `CALCULATE.action_input.expression` 正确或等价，但 teacher 给低分；
3. `ANSWER.action_input.answer` 是表达式，不是最终答案；
4. `brief_rationale` 中有正确答案，但 `action_input.answer` 错；
5. teacher 可能被 `reasoning_attempt` / `brief_rationale` 误导，而没有坚持 payload-first；
6. `U_rel = base_value * teacher_score - cost + bonus` 结构性抬高 `ANSWER`，压低 `CALCULATE / CLARIFY / REFUSE`；
7. rejected completion 中仍有“lower utility”等模板化文本，可能造成 DPO 学到文本风格 marker。

本轮修改的基本原则：

```text
不重跑 rollout；
先基于已有 artifacts 做 teacher relabel；
teacher 必须先显式抽取 candidate_evidence，再打 candidate_utility；
数学任务增加 evidence-score consistency guardrail；
U_rel 去掉 base_value 乘法；
最终 pair 可选 pairwise verification；
下一轮 rollout 再调整 student schema 顺序。
```

---

## 1. 不重跑 rollout，先做 relabel

当前问题主要发生在 teacher scoring，而不是 student candidate 是否存在。

因此第一步不应重跑 vLLM rollout，而应新增 relabel pipeline：

```text
existing rollouts / mined records
→ teacher self-evidence relabel
→ evidence-score consistency guardrail
→ recompute U_rel
→ rebuild pairs
→ human review
```

推荐新增脚本：

```text
src/mcagent_boundary/scripts/03b_relabel_teacher_self_evidence.py
```

输入：

```text
mined_records.jsonl 或 teacher input records
```

输出：

```text
teacher_labels_self_evidence.jsonl
relabel_report.json
```

## 2. Teacher 改成 self-evidence judge

### 2.1 核心改动

teacher 不再直接给 `candidate_utility`。
必须先为每个 candidate 输出 `candidate_evidence`，然后基于 evidence 输出 `candidate_utility`。

也就是说，teacher 输出结构改成：

```json
{
  "semantic_tags": [],
  "meta_reflection": "",
  "candidate_evidence": [
    {
      "rank": 1,
      "action": "ANSWER",
      "payload_answer": "",
      "rationale_answer": "",
      "payload_answer_type": "final_answer|expression|empty|verbose_text|refusal_text|unknown",
      "payload_answer_correct": true,
      "rationale_answer_correct": false,
      "payload_rationale_conflict": false,
      "evidence_summary": ""
    }
  ],
  "candidate_utility": [
    {
      "rank": 1,
      "action": "ANSWER",
      "score": 0.0,
      "failure_mode": "none|wrong_answer|payload_rationale_conflict|answer_is_expression|bad_expression|useful_intermediate|correct_calculation|bad_query|bad_clarify_question|justified_refuse|over_refuse|unsafe_answer|unknown",
      "reason": ""
    }
  ],
  "candidate_reflection": [
    {
      "rank": 1,
      "action": "ANSWER",
      "reflection": ""
    }
  ],
  "recommended_action": "",
  "rationale": "",
  "preferred_over": [],
  "rubric_degenerate": false
}
```

### 2.2 为什么这样做

这些 evidence 本来确实可以被 teacher “内在地”判断出来，但如果不要求它显式输出，teacher 很容易凭整体 impression 给分。现在把 evidence 变成显式字段，可以让程序检查 teacher 是否承认 payload 错、teacher 是否仍给高分、expression 是否被识别为等价计算。

## 3. Teacher prompt 具体修改

### 3.1 修改 `teacher_tag_reflect.md`

在 system/rubric 后追加以下段落：

```md
## Mandatory self-evidence before scoring

Before assigning `candidate_utility` scores, you MUST complete `candidate_evidence` for every candidate.

You must treat `action_input` as the executable payload.
`brief_rationale` and `reasoning_attempt` are explanations only.
They must NOT override the executable payload.

### ANSWER evidence rules

For every ANSWER candidate:

1. Extract `action_input.answer` as `payload_answer`.
2. Extract any explicit final answer from `brief_rationale` as `rationale_answer` if present.
3. Compare `payload_answer` with the gold/reference.
4. Set `payload_answer_correct`.
5. Set `rationale_answer_correct` if `rationale_answer` is present.
6. Set `payload_rationale_conflict=true` if payload and rationale imply different final answers.
7. Set `payload_answer_type`:
   - `final_answer`: a direct final answer
   - `expression`: an unevaluated expression rather than a final answer
   - `empty`: empty or missing answer
   - `verbose_text`: long text with unclear final answer
   - `refusal_text`: answer payload is actually a refusal
   - `unknown`: cannot determine

Scoring constraints for ANSWER:

- Score ANSWER using `action_input.answer`, not `brief_rationale`.
- If `payload_answer_correct=false`, score ANSWER <= 0.2.
- If `payload_rationale_conflict=true`, score ANSWER <= 0.2 and use failure_mode=`payload_rationale_conflict`.
- If `payload_answer_type=expression`, score ANSWER <= 0.4 unless you explicitly verify that the expression evaluates to the gold/reference answer.
- If `payload_answer_correct=true` and the answer is self-contained, score ANSWER >= 0.8 unless the task requires SEARCH, CLARIFY, or REFUSE.

### CALCULATE evidence rules

For every CALCULATE candidate:

1. Extract `action_input.expression`.
2. Decide whether the expression is concrete, executable, and relevant.
3. If the expression can be evaluated mentally or symbolically, compare its result with the gold/reference.
4. Mark expression relevance:
   - `direct_final`: expression directly computes the final answer
   - `useful_intermediate`: expression is useful but not the final answer
   - `irrelevant`: expression does not help answer the question
   - `unparsable`: expression is invalid or empty

Scoring constraints for CALCULATE:

- If the expression directly evaluates to the gold/reference answer, score CALCULATE >= 0.8.
- If the expression is a useful intermediate computation, score CALCULATE between 0.5 and 0.7.
- If the expression is empty, unparsable, or irrelevant, score CALCULATE <= 0.2.
- Do not penalize CALCULATE merely because the expression is algebraically equivalent rather than textually identical to the gold answer.

### General payload-first rule

- Do not reward information that appears only in `brief_rationale` if the executable `action_input` payload is wrong.
- If candidate evidence conflicts with your initial intuition, follow candidate evidence.
- The gold/reference is provided only for judging utility.
- Do NOT use the gold/reference to repair candidate action_input.
- Do NOT invent tool observations.
- Score the candidate exactly as emitted by the student.
```

### 3.2 修改 `teacher_action_recommend.md`

确保 user prompt 中包含以下字段：

```md
Question:
{question}

Gold/reference:
{gold_reference}

Student reasoning attempt:
{reason_attempt}

Student uncertainty summary:
{uncertainty_summary}

Student ranked candidates:
{student_candidates}

Candidate logprob/process features:
{process_features}

Semantic hints:
{semantic_hints}

Important: You must first output candidate_evidence for every candidate, then candidate_utility.
Follow the payload-first rules exactly.
Return JSON only.
```

## 4. `U_rel` 公式修改：去掉 base_value 乘法

### 4.1 当前问题

如果当前实现为：

```python
u = base_value[action] * teacher_score - action_cost[action] + semantic_bonus
```

且配置中：

```yaml
base_value:
  ANSWER: 1.0
  SEARCH: 0.6
  CALCULATE: 0.6
  CLARIFY: 0.5
  REFUSE: 0.4
```

则会结构性偏向 `ANSWER`，压低非 ANSWER 动作。

### 4.2 修改要求

将 `utility_rel()` 改为：

```python
u = teacher_score - action_cost[action] + semantic_bonus
```

或：

```python
u = teacher_score - action_cost[action] + semantic_bonus + action_prior[action]
```

其中 `action_prior` 最大绝对值不超过 0.05。默认推荐不使用 action_prior。

### 4.3 配置建议

```yaml
scoring:
  action_cost:
    SEARCH: 0.10
    CALCULATE: 0.05
    CLARIFY: 0.10
    ANSWER: 0.0
    REFUSE: 0.0

  action_prior:
    ANSWER: 0.0
    SEARCH: 0.0
    CALCULATE: 0.0
    CLARIFY: 0.0
    REFUSE: 0.0
```

如果保留 `base_value` 字段，只作为 backward compatibility，不参与 v0.2.5 主路径。

## 5. Evidence-score consistency guardrail

### 5.1 目标

不强行用程序替代 teacher，但要防止 teacher 自己输出的 evidence 与 score 明显矛盾。

### 5.2 新增函数

建议新增：

```text
src/mcagent_boundary/annotation/validate_teacher_evidence.py
```

核心函数：

```python
def apply_evidence_score_guardrail(label: dict, *, dataset: str) -> dict:
    ...
```

### 5.3 数学任务 guardrail

对 `gsm8k` / `math`：

```python
if action == "ANSWER":
    if evidence.get("payload_answer_correct") is False:
        score = min(score, 0.2)
        failure_mode = failure_mode or "wrong_answer"
    if evidence.get("payload_rationale_conflict") is True:
        score = min(score, 0.2)
        failure_mode = "payload_rationale_conflict"
    if evidence.get("payload_answer_type") == "expression" and evidence.get("payload_answer_correct") is not True:
        score = min(score, 0.4)
        failure_mode = failure_mode or "answer_is_expression"
    if evidence.get("payload_answer_correct") is True:
        score = max(score, 0.8)

if action == "CALCULATE":
    relevance = evidence.get("expression_relevance")
    if relevance == "direct_final" or evidence.get("expression_matches_gold") is True:
        score = max(score, 0.8)
    elif relevance == "useful_intermediate":
        score = max(min(score, 0.7), 0.5)
    elif relevance in {"irrelevant", "unparsable"}:
        score = min(score, 0.2)
```

### 5.4 非数学任务 guardrail

对 `in3`：

```python
if action == "CLARIFY" and evidence.get("targets_critical_slot") is True:
    score = max(score, 0.8)

if action == "CLARIFY" and evidence.get("targets_critical_slot") is False:
    score = min(score, 0.3)
```

对 `mintqa`：

```python
if action == "SEARCH" and evidence.get("query_specific_and_relevant") is True:
    score = max(score, 0.75)

if action == "SEARCH" and evidence.get("query_specific_and_relevant") is False:
    score = min(score, 0.3)
```

对 `or_bench`：

```python
if should_refuse is True and action == "REFUSE":
    score = max(score, 0.8)

if should_refuse is True and action == "ANSWER":
    score = min(score, 0.2)

if should_refuse is False and action == "REFUSE":
    score = min(score, 0.3)

if should_refuse is False and action == "ANSWER":
    score = max(score, 0.75)
```

### 5.5 输出 diagnostics

guardrail 不应静默修改。每条修改都应写入：

```json
{
  "guardrail_applied": true,
  "guardrail_reasons": [
    "answer_payload_wrong_score_capped",
    "calculate_direct_final_score_floored"
  ],
  "original_score": 0.8,
  "guardrailed_score": 0.2
}
```

## 7. Pairwise verification for final pairs

### 7.1 目的

teacher scalar score 有时会出错。最终 pair 进入 DPO 前，可以对高风险 pair 做 pairwise verification。

### 7.2 触发条件

只对以下样本触发：

```text
dataset in {gsm8k, math}
OR chosen_action in {SEARCH, CLARIFY, REFUSE}
OR utility_gap <= 0.20
OR payload_rationale_conflict=true
OR answer_is_expression=true
```

### 7.3 Pairwise prompt

新增 prompt：

```text
src/mcagent_boundary/prompts/teacher_pairwise_verify.md
```

内容：

```md
You are verifying a preference pair for action calibration.

Given:
- question
- gold/reference
- decision state
- candidate A
- candidate B
- candidate evidence for both

Decide which candidate is the better next action at this state.

Rules:
- Judge executable action_input payload, not only rationale.
- Do not repair candidates.
- If ANSWER payload is wrong, it should lose to a useful CALCULATE/SEARCH/CLARIFY/REFUSE candidate.
- If CALCULATE expression is correct or directly useful, do not penalize it for not being a natural-language final answer.
- Return JSON only.

Return:
{
  "preferred": "A|B|tie|uncertain",
  "reason": "",
  "pair_accepted": true
}
```

### 7.4 位置交换

为减少 pairwise judge 的位置偏差，建议对高风险 pair 做交换验证：

```text
A=chosen, B=rejected
A=rejected, B=chosen
```

保留条件：

```text
两次结果一致支持原 chosen > rejected
```

若不一致：

```text
drop 或送 human_review
```

## 8. 修改 DPO completion reflection，避免 rejected marker

### 8.1 当前问题

如果 rejected completion 中含有：

```text
Alternative choice: picking X despite its lower local utility...
```

DPO 可能学到文本 marker，而不是 action preference。

### 8.2 修改要求

不要在 rejected 文本中出现：

```text
lower utility
rejected
worse
alternative despite
```

### 8.3 推荐方案

让 teacher 输出每个 candidate 的 reflection：

```json
"candidate_reflection": [
  {
    "rank": 1,
    "action": "ANSWER",
    "reflection": "I can answer directly because the payload is correct and self-contained."
  },
  {
    "rank": 2,
    "action": "CALCULATE",
    "reflection": "A calculation would verify the arithmetic step."
  }
]
```

构造 chosen/rejected 时：

```python
chosen_reflection = candidate_reflection[chosen.rank]
rejected_reflection = candidate_reflection[rejected.rank]
```

短期 fallback：

```python
reflection = candidate.get("brief_rationale") or f"I considered {candidate['action']} under the current uncertainty."
```

## 9. 下一轮 rollout 再改 student schema 顺序

不建议现在为了 schema 顺序重跑昂贵 rollout。
但下一轮 rollout 应调整 candidate 字段顺序。

### 9.1 当前顺序

```json
{
  "rank": 1,
  "action": "ANSWER",
  "confidence": 0.8,
  "action_input": {"answer": "..."},
  "brief_rationale": "..."
}
```

### 9.2 下一轮建议顺序

```json
{
  "rank": 1,
  "action": "ANSWER",
  "confidence": 0.8,
  "brief_rationale": "why this action is appropriate; do not include final numeric answer",
  "action_input": {"answer": "final answer only"}
}
```

### 9.3 Student prompt 增加规则

```md
For ANSWER candidates:
- The final answer must appear only in `action_input.answer`.
- Do not put the final numeric/symbolic answer in `brief_rationale`.
- `brief_rationale` should explain why ANSWER is appropriate, not redo the computation.
- For math questions, `action_input.answer` must be the final scalar/symbolic answer, not an unevaluated expression.
```

这可以减少“先写错 answer，后面 rationale 算对”的问题。

  "chosen_action": "",
  "rejected_action": "",
  "human_pair_accept": true,
  "teacher_error": false,

### 10.3 通过阈值

建议：

```text

SEARCH/CLARIFY/REFUSE per-action pair_accept_rate >= 80%
```

未达到时，不进入 DPO。

## 12. v0.2.5 验收标准

1. Teacher 输出中必须含 `candidate_evidence`；
2. Teacher 输出中必须含 `candidate_utility`；
3. `ANSWER` 分数必须遵守 payload-first hard caps；
4. `CALCULATE` 分数必须遵守 expression relevance hard floors/caps；
5. `U_rel` 不再使用 `base_value * teacher_score`；
6. 所有 guardrail 修改都有 diagnostics；
7. rejected completion 不再包含 “lower utility / rejected / worse” 等显式负面 marker；
8. human review 中 `wrong_answer_payload_high_score` 明显下降；
9. human review 中 `correct_calculate_low_score` 明显下降；
10. 通过人工 pair accept rate 阈值后才允许 DPO 训练。

---

## 13. 最终原则

v0.2.5 的原则是：

```text
student candidate 不修；
teacher 必须显式验 payload；
utility 必须 follow payload evidence；
数学可验证错误必须 guardrail；
DPO pair 不能带文本 marker；
先 relabel，再训练。
```

这能在不重跑昂贵 rollout 的前提下，最大限度修复当前 pair 质量问题。
